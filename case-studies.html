/01
NomaWEB APP · AIConcept project

Booking statuses that answer the real question

Role
UX/UI design & AI-assisted build
Tools
Figma, Claude Code
Focus
UX writing, status design

THE PROBLEM

Bookings were labeled "Confirmed" or "Unconfirmed". Travelers couldn't tell whether they had already paid or still owed money on the trip. "Unconfirmed" mixed two different situations: not booked yet, or waiting for the provider. Meanwhile, the summary above already talked about money ("$1,864 paid · $1,640 to pay on the trip"), so the summary and the statuses spoke two different languages.

try it!
  1. 1Confirmed: the booking or the payment? The label doesn't say.
  2. 2The summary already talks about money paid and money to pay.
  3. 3"Unconfirmed · Pending confirmation": not booked, or waiting for the provider?
  4. 4The sidebar repeats the same ambiguous labels.
  1. 1Three states that match the money summary: 5 paid, 3 reserved, 1 pending.
  2. 2Reserved means booked, pay later.
  3. 3Every reserved booking says how and where to pay.
  4. 4The sidebar uses the same language as the list.

THE DECISION

I replaced the two labels with three states based on what the traveler needs to do:

  • PaidBooked and paid, nothing to do.
  • ReservedBooked, pay later, always with how and when ("Pay at the station", "Pay at check-in").
  • PendingNot booked yet, needs action.

Each state has its own visual treatment, so they can be told apart at a glance.

THE RESULT

  • Statuses now match the money summary.
  • Travelers know exactly what is left to pay and where.
  • The same states feed the trip overview and let the assistant answer "what's still pending?".

/02
KindaWEB APP · HABITSConcept project

Putting the summary where it helps

Role
UX/UI design & AI-assisted build
Tools
Figma, Claude Code
Focus
Information architecture

THE PROBLEM

The Insights page had a large summary card that showed one pattern and linked to the full list on the same page. Clicking "See all patterns" only scrolled down a few hundred pixels, and the same pattern appeared twice, in the card and at the top of the list. The card took space from the content it was pointing to.

Before · Insights

  1. 1A summary card on the same page as the full list.
  2. 2This button only scrolls down the same page.
  3. 3The same pattern again, a few hundred pixels below.

After · Overview

  1. 1The summary now lives in the Overview, one pattern at a time.
  2. 2Opens Insights right at the patterns list.
See all patterns→

After · Insights

  1. 1The patterns section gets the spotlight.
  2. 2Filters up front to explore by type.
  3. 3Weekly consistency now uses the full width.

THE RESULT

  • No repeated content.
  • Insights reads top to bottom without jumps.
  • The Overview gains a gentle entry point to the patterns.

THE DECISION

Summary where people don't see the detail yet; detail where it lives.

  • The card moved to the Overview, as a preview that shows one pattern at a time.
  • "See all patterns" now opens Insights right at the list.
  • On Insights, the patterns section gets the spotlight: a bigger title, filters up front, and weekly consistency at full width.
